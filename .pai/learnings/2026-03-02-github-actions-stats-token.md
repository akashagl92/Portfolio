# Learning: GitHub Actions Runner Token Scope Limitations

**Date:** 2026-03-02
**Context:** During the dynamic assembly of the portfolio README, the total repository contributions counter inexplicably dropped from 428 across 10 repositories to 112 across 3 repositories.

## Trigger
A rebase conflict resolution favored the `data.json` artifact generated by the remote GitHub Action over the local version. This remote artifact contained wildly reduced contribution counts.

## Root Cause
The `fetch_contributions.py` script relies on the GitHub REST API to count total commits and summarize language composition. 
When executing locally via the `.env` file, the script used a Personal Access Token (PAT) with full `repo` scopes, allowing it to correctly traverse both public and private repositories (e.g., Moltbot, AI Astrology).
When executing via GitHub Actions, the workflow utilized a specific scoped token (`PORTFOLIO_GITHUB_PAT` or the default `GITHUB_TOKEN`). This token lacked the permission scopes required to view private repositories. Consequently, the API silently omitted all private repo data, returning only the 3 public repositories and their associated 112 commits, silently creating an inaccurate data artifact.

## Resolution
1. The accurate `data.json` was regenerated locally via an offline fetch using the fully-scoped PAT.
2. The accurate data was propagated across all portfolio paths.
3. The dynamic README was re-assembled with the accurate 428 commit count.

## Permanent Preventative Measures
- When an automated API fetch suddenly produces drastically lower numbers than a previous run, automatically suspect authentication scope mismatch rather than logic failure.
- Moving forward, CI ingestion tasks that require deep architectural insights across private boundaries must be furnished with strictly audited PATs containing explicit private repo read scopes.
